# 讲解动画设计（写 storyboard.md 和 anim.js 之前必读）

## 目标：图会"讲题"，而不是一张逐渐画满的插图

差的做法（真实发生过）：图形一次画好，之后每句话只是在图上多出一条线或一个标签，所有解释都写在右边板子上。观众只能盯着板子读字，图只是背景。`render.mjs motion` 会把这种句子标成 `STATIC` / `POP`。

好的做法：**每句旁白，图上都有一个动作把这句推理"演"出来**。说"CD 等于 AB 的一半"，就让 CD 的复制品转到 DA、DB 上和它们重合；说"弧长除以半径得圆心角"，就让半径沿着弧滚过去；说"回到空间图"，就让俯视图旋转回立体图。板子只负责记下结论。

生物题使用 [biology-visuals.md](biology-visuals.md)：从完整细胞进入同一细胞器，演出结构和机制变化，再回到整体。目标是让细胞、膜、线粒体等成为可辨认的对象，不能只是用几颗圆点配一块文字板。空间层次和具体形态先服务于解释，不用无关特效填满画面。

## 每句旁白的四个动作：指 → 动 → 留 → 连

| | 做什么 | 怎么写 |
|---|---|---|
| **指** | 旁白提到哪个元素，它就被点亮；无关元素变淡 | `glow(pts, col, bump(lt, at(k, f)))` 在线段下面画荧光笔；`grp(0.3, ...)` 画次要元素；intro 用 `hiBox` |
| **动** | 一个能体现推理的动作，0.6~1.5 秒，在这句的中段完成 | 见下面的动作表：`slideSeg`、`movePoly`、`camTween`、动点、`countTo`、生长的辅助线…… |
| **留** | 动作结束后留下标记，后面的句子可以引用 | `rightM` 直角、`tickM` 等长、`paraM` 平行、`angM` 角、数值标签、半透明着色 |
| **连** | 板子上的算式和图上的量用**同一种颜色**；复杂时用 `callout` 箭头从图指向板子那一行 | 已知量蓝、所求/答案红、辅助线/结论绿、强调黄 |

一句话里只做**一个主要动作**。多个动作挤在一句里，观众跟不上。

## 动作表：推理 → 动画

| 推理 / 说法 | 图上的动作 | 代码 |
|---|---|---|
| 已知某条边、某个量 | 这条边 glow 闪一下，数值弹出 | `glow` + `bump`；`txt(..., {pop: P(...)})` |
| 取中点 / 取某点 | 一个点沿线段滑过去停在该点，再出现等长标记 | `mix2(A, M, eio(P(...)))` + `dot`；`tickM` |
| 作辅助线 | 虚线从起点"长"出来 | `draw([P, Q], {dash: [12, 10], p: P(...)})` |
| 两条线段相等 | 一条的复制品平移+旋转到另一条上重合 | `slideSeg(a, b, c, d, eio(P(...)))` |
| 两线平行 | 一条的复制品平移到另一条上；然后画平行标记 | `slideSeg` + `paraM` |
| 两角相等（内错角、同位角） | 一个角的弧 + 着色扇形复制后移到另一个角上 | `angM` 画在 `movePoly` 移动后的三个点上 |
| 垂直 | 直角符号画出，线段 glow | `rightM` |
| 全等 | 一个三角形着色复制，平移/旋转（必要时翻折）叠到另一个上 | `fillPts(movePoly(tri, dx, dy, rot))` |
| 相似 / 中位线 | 小三角形着色，放大 k 倍叠到大三角形上（或反过来） | `movePoly(tri, dx, dy, 0, k)` |
| 勾股 / 面积 | 各边上的正方形或面积块着色，数字数出来；割补就移动面积块 | `fillPts` + `movePoly` + `countTo` |
| 求出一个长度 | 这条线 glow 从一端扫到另一端，旁边数字从 0 数到结果 | `glow(pts, col, 1)` 配合 `draw(..., {p})`；`countTo(0, v, e, 1)` |
| 圆心角 / 弧长 | 弧线沿圆周长出来，同时半径旋转扫过 | `ellPts` + `draw({p})`；半径端点 `[cx + r cos a, cy + r sin a]`，a 随时间变 |
| 圆锥侧面积 / 展开图 | 侧面沿一条母线剪开，展开成扇形（见下方代码） | `unrollCone` 配方 |
| 线面垂直、投影 | 从点"落下"一条虚线到底面，落点出现直角符号 | `L3(P, foot, {dash, p})` + `rightM(pr(...))` |
| 立体 → 底面俯视图 | **同一个 3D 模型**把相机转到正上方，不要硬切换到另一张图 | `camTween({pitch: .52, yaw: .2}, {pitch: PI / 2, yaw: 0}, e)` |
| 面面平行 | 两个平面半透明着色，一个平面的复制品平移到另一个上 | `fillPts` 画平面四个点；3D 点做 `mix3` 平移 |
| 线在面内 / 动点 | 点在线段上来回移动，相关直线跟着动，始终保持性质（颜色不变、标记不变） | `const u = 0.5 + 0.5 * Math.sin(...)` 或 `eio(P(...))` |
| 函数单调性 / 最值 | 动点沿图像移动，读数 `(x, y)` 跟着变化；到最值处停下闪一下 | `fnPts` + `ax.S` + `countTo` |
| 参数变化 | 图像随参数形变（参数值写在旁边并计数） | 每帧用插值后的参数重算 `fnPts` |
| 不等式 / 取值范围 | 数轴或图像上对应区间着色，端点空心/实心 | `fillPts` + `circ` |
| 行程 / 追及 | 用"题目时间"驱动人物移动，旁边时钟和路程读数实时变化 | `token` + `countTo`；位置 = 路程函数(时间) |
| 列方程 / 代数变形 | 图上对应量 glow，同色写到板子；移项时让那一项的文字从左边滑到右边并变号 | `txt` 位置用 `lerp` |
| 分类讨论 | 同一张图画两种情况：依次切换，或左右各一个小图 | `grp` 淡入淡出 / `scaleAt` 缩小 |
| 验算 | 把答案代回：图上的数值更新到答案，性质标记（平行、相等）亮起 | `countTo` + `bump` |

## 两个完整示例（照着学）
- `template/`（anim.js + storyboard.md）：平面几何。线段复制品滑动证相等、外接圆、延长成矩形、对角线旋转重合、数值计数。
- `examples/cone-parallel/`：立体几何。射影（P 落到 O，PA 被压到 AO）、两段 OA 铺满 PA、侧面展开成半圆、同一模型转到俯视图、60° 扇形绕 OC 中点转半圈（内错角）、△AOQ 放大成 △APB（中位线）、平面 QOC 沿 OB 平移进平面 PBD、动点 T。
  用法：新题是立体几何时，从这个示例复制 `cone()` / `camTween` / `unrollCone` 的写法，而不是从零写。

## 容易被糊弄过去的地方（motion 检查查不出来，你必须自己守住）
- **只让某条线闪来闪去不算"动"。** glow/bump 是"指"。storyboard 的"动"只写 glow/闪/高亮/出现 会被 `--check` 拒绝。
- **计算幕也要有图上的动作**：
  - "代入已知数" → 图上对应的数值标签飞进板子上的算式：`flyText('2', 图上2的位置, blPos(1, 180), eio(P(at(0, 0.2), 1.0)))`
  - "求出 BC = 10" → BC 旁的数字从 0 数到 10（`countTo`），同时 BC 从一端 glow 扫到另一端
  - "比例 AD/AB = DE/BC" → 小三角形的边放大后分别落到大三角形的对应边上（`slideSeg`），同色成对出现
- **题目里的每个对象都必须画出来。** 写 storyboard 前先列"图形清单"：所有点、线段、平行/垂直关系、已知长度。截图检查时逐项核对，漏画（例如题目说 DE∥BC 却没画 DE）是严重错误，比动画不好看更严重。
- 点的位置要符合数据：AD = 2、DB = 3 → D 在 AB 上 2/5 处；平行就真的平行。用 `mix2(A, B, 2 / 5)` 这样算坐标，不要目测。

## 常用写法

```js
SC.key = (lt, S) => {
  const { P, at } = S;
  // 指：这句（第 0 句）提到 CD → CD 下面的荧光笔闪一下；bump 在 at(0) 后 1.2 秒内 0→1→0
  glow([Cp, Dp], C.red, bump(lt, at(0)));
  // 次要元素变淡：在"动"的时候把其余部分画成 0.3 透明
  const focus = P(at(0, 0.15), 0.4) * (1 - P(at(1), 0.4));
  grp(1 - 0.7 * focus, () => drawRest());
  // 动：CD 的复制品转到 DA 上（eio 让它慢-快-慢）
  slideSeg(Cp, Dp, Dp, Ap, eio(P(at(0, 0.25), 1.0)));
  // 留：动作完成后画等长标记
  tickM(Dp, Ap, 1, C.red, P(at(0, 0.6), 0.4));
  // 连：板子同色
  bl(1, 'CD = DA = DB', at(0, 0.5), lt, { c: C.red });
};
```

**立体 ↔ 俯视图（连续过渡）**
```js
const e = eio(P(at(0), 1.5));                        // 进入本幕：1.5 秒转到俯视
camTween({ pitch: 0.52, yaw: 0.2, s: 160 }, { pitch: PI / 2, yaw: 0, s: 220 }, e);
cone(st);                                            // 同一个画图函数；俯视时 z 被忽略，底面圆就是正圆
```
离开俯视图时再反向 `camTween(top, oblique, eio(P(at(k), 1.5)))`。

**圆锥侧面展开成扇形（unrollCone 配方）**：母线长 l、底面半径 r，展开扇形圆心角 = 2πr / l。
```js
// e: 0 = 立体圆锥侧面, 1 = 平面扇形；apex2D 是扇形圆心在屏幕上的位置，Ls 是母线在屏幕上的长度
function unrollCone(e, apex2D, Ls, r, l, col = C.blue) {
  const n = 60, theta = 2 * PI * r / l, pts3 = [], pts2 = [];
  for (let i = 0; i <= n; i++) {
    const a = i / n * 2 * PI;                                    // 底面圆周上的点（3D）
    pts3.push(pr([r * Math.cos(a), r * Math.sin(a), 0]));
    const b = -PI / 2 - theta / 2 + theta * i / n;               // 扇形弧上的对应点（2D）
    pts2.push([apex2D[0] + Ls * Math.cos(b), apex2D[1] + Ls * Math.sin(b)]);
  }
  const rim = tween(pts3, pts2, e), top = mix2(pr(G.P), apex2D, e);
  fillPts([top, ...rim], col, 0.15);
  draw(rim, { c: col, w: 4 }); draw([top, rim[0]], { c: col, w: 4 }); draw([top, rim[n]], { c: col, w: 4 });
}
```
（示意即可：中间过程不必是严格的几何展开，观众看到"剪开—摊平"就懂了。）

**动点保持性质**
```js
const u = 0.5 + 0.45 * Math.sin(PI * 2 * P(at(5), S.dur(5)));   // 这句话里来回一次
const T = mix3(G.O, G.C, u);
L3(G.Q, T, { c: C.red, w: 6 });                                  // QT 跟着动
glow([pr(G.Q), pr(T)], C.red, 0.6);                              // 始终在平面 QOC 的着色区域里
```

## 版面与节奏
- 几何解题可使用左图右板布局；机制讲解让模型成为主要画面，名称直接标在结构附近，板书只保留必要结论。不要机械地把所有学科都压在左半边，再用右半屏重复旁白。
- 需要两个视图时，用 `camTween` 或 `scaleAt` 过渡，不要两张图挤在一起。生物课的整体与局部来自同一模型；放大后保留定位线索，返回时保持对象状态与空间关系。
- 每幕开头承接上一幕结尾的状态（同一个画图函数，参数设为 1），再开始本幕的新动作。
- 动作放在句子的 15%~80% 之间：开头留给"指"，结尾留给"留"。
- 同一幕里用过的颜色含义不要变。
- 需要强调答案时：`stamp` 盖章 + 图上对应元素 glow。
- 开头用一个具体视觉现象和可解答的问题建立兴趣；尽快让画面开始解释。不要先放长片头或整屏目录。
- 镜头运动用于定位和改变观察尺度；关键机制发生时镜头稳定。让旁白、标签和主要动作围绕同一个对象，避免观众一边追镜头一边读多行文字。
- 先做约 45~60 秒样片，检查模型识别、空间连贯、因果过程、配音字幕，再批量导出完整课程。像素一直变化不代表更吸引人，也不代表讲清楚了。

## storyboard.md（写 anim.js 之前必须先写）

格式见 `template/storyboard.md`：每句一行，`| 幕id 句号 | 旁白要点 | 指 | 动 | 留 | 板书 |`。
- 除第一幕（读题）和最后一幕（回顾）外，**每一行的"动"都必须填写**，而且是上面动作表里的动作，不能写"显示""出现""标出"这种只是出现的词（出现可以写在"留"里）。
- 每一幕至少有一句的"动"是连续运动（滑动、旋转、平移、展开、相机转动、动点、数字计数）。
- `build_audio.py --check` 会检查每句是否都有一行、"动"是否为空。

写完 anim.js 后，`node render.mjs motion` 自动检查：
- `STATIC`：这句图上完全没变化 → 必须改（加 glow/bump 指一下，或加动作）。
- `POP`：只是出现了东西 → 可以，但每幕至少要有一句 `MOVE`。
- `MOVE`：这句里图一直在动。
报告在 `build/motion_report.txt`，不通过退出码为 1。确实不需要动的句子（很少见），在 `episode.json` 的 `"static_ok": ["幕id 句号"]` 里列出并在交付时说明理由。
