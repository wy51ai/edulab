# 写旁白脚本：episode.json + script.json

## episode.json

```json
{
  "title": "直角三角形斜边中线：求CD的长",
  "output_name": "斜边中线_Median_to_Hypotenuse",
  "pop_scenes": ["key", "solve"]
}
```
- `title`：写进 mp4 元数据。
- `output_name`：输出 `WS/<output_name>.mp4` 和 `.srt`。格式 `中文短名_English_Name`，不要有空格和 `/`。
- `pop_scenes`：这些幕里每句旁白开始时加一个轻"啵"音效（用在关键结论、列式计算幕）。幕切换的"嗖"音效是自动的。

## script.json 格式

```json
[
  {"scene": "intro", "lines": [
    {"zh": "两条直角边 AC = 3，BC = 4。",
     "tts": "两条直角边，AC等于三，BC等于四。",
     "en": "The legs are AC = 3 and BC = 4."}
  ]},
  {"scene": "solve", "lines": [ ... ]}
]
```

| 字段 | 用途 | 规则 |
|---|---|---|
| `scene` | 幕 id | 英文标识符（`intro`、`figure`、`key`、`solve`、`check`、`outro`…），不重复；anim.js 必须有同名 `SC.<id>` 和 `TAGS.<id>` |
| `zh` | 中文字幕 | 正常数学写法：`AB = 5`、`∠C = 90°`、`AB^2`（`^2` 显示为 ²，`_2` 显示为 ₂）。可含读音标注，字幕里会自动去掉 |
| `tts` | 实际朗读的文本 | **只写能念的中文**（见下表）。省略时用 `zh` 朗读，所以 `zh` 里有数字或符号时必须写 `tts` |
| `en` | 英文字幕 | 意思对应即可，≤ 95 字符 |
| `pause_after` | 本句结束后的思考时间 | 可选，0~30 秒的有限数值；默认 0。音频无旁白，字幕保留 |
| `theorem` | 本句使用的定理与条件 | 可选对象，包含 `name`、非空 `conditions` 数组、`conclusion`；每个条件包含 `claim` 和 `reason` |

**建议每句都写 `tts`**，哪怕和 zh 一样，这样不会漏。

## 幕的结构（标准 5~7 幕）

| 幕 id（示例） | 内容 | 画面 |
|---|---|---|
| `intro` | 标题 + **逐条读题**：一句一个条件，最后一句读"求什么" | 题目图片卡片，读到哪条框哪条，下方出条件小标签 |
| `figure` / `setup` | 画图、标已知量、明确要求的量 | 左边逐步画图形；右边板子列"已知/求" |
| `key` | 关键思路/定理，**并用动画说明为什么** | 图上加辅助线、着色、对应关系 |
| `solve` / `equation` | 列式计算，一句一步 | 板子逐行写算式，最后 `stamp` 盖章答案 |
| `check`（推荐） | 代回验算、检查取值范围 | 图上标实际数值 |
| `outro` | 方法回顾（3 张卡片）+ 报答案 + "我是小气团，下道题见！" | 卡片 → 吉祥物 + 答案气泡 |

多问题（第(1)(2)问）：每问一个 key/solve 组合，id 如 `key1`、`solve1`、`key2`、`solve2`。

## 写好旁白的规则

1. **一句一个点**，15~30 字最好；> 36 字宽（`--check` 会 warn）字幕就会折两行，折行后字幕框顶部升到 y≈860。
2. 口语化、像老师讲课：“来看这道题”、“为什么？”、“关键在于……”。
3. 按画面顺序说：先说"看这条辅助线"，画面上才出现辅助线。
4. 数值要和解答完全一致；验算幕要真的代回去算。
5. 读题的句子要和题目原文对应，因为每句要对应一个高亮框。
6. 按推理复杂度安排时长；多道独立大题优先拆开。关键问题后留出思考时间，不为凑时长省略证明。

例如提问句添加 `"pause_after": 4`，下一句才讲答案。`timeline.json` 中 `end` 仍是旁白结束时刻，新增 `hold_end` 是字幕保留结束时刻；动画的 `S.dur(k)` 不被拉长。`S.cue(k+1)` 自动包含这段停顿。未使用新字段的脚本时序不变。

定理条件声明和教学审阅方法见 [teaching-quality.md](teaching-quality.md)。检查器只检查声明结构，不验证数学正确性。

## 数学式子的口语写法（tts 字段）

`--check` 会拦截 tts 里的阿拉伯数字和符号。对照表：

| 写法 | tts 里写 |
|---|---|
| `AC = 3` | AC等于三 |
| `60 m`、`7.5 秒`、`4 m/s` | 六十米、七点五秒、每秒四米 |
| `1200`、`4800` | 一千二百（或一千二）、四千八百 |
| `-3` | 负三 |
| `x²`、`x³`、`xⁿ` | x的平方、x的立方、x的n次方 |
| `√3`、`2√3` | 根号三、二倍根号三 |
| `3/4`、`a/b` | 四分之三、b分之a |
| `(60 − 7t)/60` | 六十分之，六十减七t |
| `a(b + c)` | a乘括号b加c |
| `a × b`、`a ÷ b`、`a · b` | a乘b、a除以b、a点乘b（向量） |
| `a ≥ b`、`a ≤ b`、`a ≠ b`、`≈` | a大于等于b、a小于等于b、a不等于b、约等于 |
| `∠ABC = 90°` | 角ABC等于九十度 |
| `△ABC ∽ △DEF`、`≌` | 三角形ABC相似于三角形DEF、全等于 |
| `AB ∥ CD`、`AB ⊥ CD` | AB平行于CD、AB垂直于CD |
| `x ∈ [0, 1]` | x属于闭区间零到一 |
| `f(x) = 2x + 1` | f x等于二x加一 |
| `f'(x)` | f x的导数（或 f 撇 x） |
| `sin α`、`cos 2x`、`tan θ` | 正弦阿尔法、余弦二x、正切西塔（不要写 sin/cos，TTS 会乱读） |
| `log₂8` | 以二为底八的对数 |
| `π` | 派 |
| 坐标 `(2, −1)`、`A(1, 0)` | 点二，负一 / 横坐标二、纵坐标负一 / 点A一，零（不要念"括号……右括号"） |
| 区间 `1 < x < 3`、`(1, 3)` | 一小于x小于三 / 开区间一到三 |
| `a₁`、`aₙ`、`Sₙ` | a一、a n、S n |
| `{aₙ}` | 数列a n |
| `P(A)` | A发生的概率 / P A |
| `%` | 百分之…… |
| `∴`、`∵` | 所以、因为 |
| `Rt△ABC` | 直角三角形ABC |
| 大写字母点名 `AB`、`BPQ` | 直接写 `AB`（pron.py 自动拆成 `A B` 逐个读；不要写 `A、B`） |
| 字母前面只有一个字（`弧AC`、`T是…` 开头） | 前面加上类别名词：`弧线AC`、`点T是…`、`线段CM等于…`（实测 `弧AC` 被读糊，`弧线AC` 正常） |

提示：
- 括号、分式很长时，拆成两句，或用逗号给 TTS 停顿："六十分之，六十减七t"。

**断句**：GLM-TTS 没有停顿标记，能控制停顿的只有标点。
- 逗号放在念的时候自然换气的地方：长主语之后、"所以/因此/于是"之前、连等式的每个"等于"之前（`O B等于根号下二加一，等于根号三`）。
- 一个分句（两个标点之间）不超过 18 个字，否则 TTS 会自己找地方停，常常停在词中间；`--check` 会 warn。
- 逗号不要把一个名词拆开：不要写 `平面，P A D`、`角，O C B`。
- 冒号、分号也会产生停顿，只在真的要停的地方用。
- 小写字母单个可以（`t`、`x`），连续小写单词（sin、log、max）会被 warn，要换成中文。
- 年份、编号之类按习惯读："二〇二五年"。

## 写完后的自检
- [ ] 每句 `tts` 都没有数字和符号（`--check` 无 ERROR）
- [ ] intro 每一句对应题目图上的一个高亮框
- [ ] 最后的答案与第 1 步你自己算的一致
- [ ] outro 最后一句报出答案
