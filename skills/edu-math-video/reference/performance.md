# 配音与视频生成提速（0.3.1）

## 做了什么

- Windows 离线配音按待生成的片段分批，每个批次只启动一次 PowerShell / SpeechSynthesizer。最多四个批次同时运行，每批最多十六句。相同文本与音色对应的音频只生成一次，已有片段继续复用。
- 原始配音已经是 48 kHz、单声道、16-bit PCM 时，直接重写为不含额外元数据的标准 WAV。采样不变；其他格式仍由 FFmpeg 转换。写入临时文件成功后才替换目标文件。
- 视频默认使用 x264 `fast`，保留 1920×1080、30 fps、CRF 18 和原 JPEG 帧质量。压缩策略变化可能略微改变文件大小与压缩后的像素；仍可使用 `medium`。
- 成功导出的 MP4 可以复用。渲染器在启动浏览器前检查输入内容和输出内容的 SHA-256，不凭文件是否存在或修改时间判断完成。

## 命令与缓存范围

```bash
node render.mjs video 4                         # 默认 fast；命中缓存时跳过导帧和编码
node render.mjs video 4 --fresh                 # 强制重新导帧与编码
node render.mjs video 4 --fresh --preset medium # 使用升级前的压缩设置
```

`4` 是并行浏览器页数。默认仍为 `6`；允许 `1..32` 的整数。并行数多不一定更快，应根据 CPU 与内存调整。`stills` 与 `motion` 保持原流程。

缓存记录保存在 `build/render-cache.json`。输入包括项目目录内的文件内容，例如动画、渲染代码、页面、模型、图片、字体、时间轴、混音与自定义数据，以及视频参数和 FFmpeg 路径/大小/修改时间。目录链接的路径与目标身份也纳入检查，循环链接不会无限遍历。排除依赖目录（`node_modules`、`.git`、`__pycache__`、`.venv`）、已由混音代表的 `build/tts`、截图目录 `build/stills` 和指定的生成报告、分块及缓存文件。输出还需匹配完整文件哈希；删除、修改或损坏 MP4 会使缓存失效。导出期间输入发生改变时不保存缓存，并提示重新生成后再交付。输入扫描失败（例如无关失效链接）时禁用本次缓存并继续导出；缓存保存失败只给出警告，不将已完成的导出标为失败。

项目之外、没有通过本地链接纳入项目的资源，以及网络资源、时间/随机数驱动的内容，不在这套静态输入检查的保证范围内。使用这些资源时，每次都传 `--fresh`。浏览器、Node 依赖、操作系统字体或渲染环境升级后也应强制重建。模板课程采用本地资源和时间轴驱动动画。

缓存用于省去相同工作的重复执行。它不替代科学、题解、读音、分镜、截图或动作检查；之前导出错误的课程也不能因复用速度快而直接交付。

## 同一课程的实测

对照使用 60.401 秒的 `mitophagy-cell` 课程、相同讲稿和 Microsoft Huihui Desktop 离线中文语音、相同语速，关闭背景音乐。设备为 Windows，AMD Ryzen 7 8840HX，12 核 / 24 逻辑处理器。视频均用四个工作页、1080p、30 fps、CRF 18；原版是提交 `a848cbb` 的 `medium`，优化版为 `fast`。冷启动项目各生成一次，重复导出使用已完成的优化项目。

| 阶段 | 原版 | 优化后 |
|---|---:|---:|
| 首次离线配音与音频构建 | 22.65 秒 | 11.84 秒 |
| 首次视频导出 | 70.15 秒 | 59.21 秒 |
| 上述两项合计 | 92.81 秒 | 71.04 秒 |
| 输入未改的重复视频导出 | 每次重新导出 | 0.74 秒 |

首次配音加导出用时减少约 23%。这些数字不含题目识别、解题、讲稿与动画创作，也不代表其他机器或课程的固定耗时。对短片的导帧批处理与线程限制实验没有稳定收益，因此没有采用。

验证：十一段配音、完整混音的 PCM 采样及时间轴与原版完全相同；两段 MP4 的 1813 帧完整比较 SSIM 为 0.997852，优化成品音视频全程解码无错误。SSIM 衡量压缩画面相似度，不衡量教学质量。

## 已有视频项目升级

新项目通过 `new_video.sh`、`new_video.ps1` 或 `create_biology_demo.py` 自动获得新运行文件。已有项目先备份，再从新版 `template/` 复制以下文件：

```text
build_audio.py
audio_io.py
windows_tts.py
windows_tts.ps1
render.mjs
render_options.mjs
render_cache.mjs
```

这些文件依赖已有的音频、教学与动作检查帮助模块。若项目早于 0.3.0，优先在新项目中迁移课程，并保留自己的 `anim.js`、`index.html`、`script.json`、`episode.json`、`storyboard.md`、模型/素材和读音词表。不要用模板覆盖已编写的课程。升级后先运行 `build_audio.py --check` 和课程的预览检查，再生成音频与视频；首次使用 `--fresh`。
